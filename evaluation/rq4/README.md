# RQ4：失败特征分析

## 分析主线

RQ4 解释 VLAD-Fuzz 发现了什么，不重复 RQ2 的方法比较或 RQ3 的组件消融。
论文稳定报告六类可观测失败：collision、lane_invasion、out_of_bounds、timeout、
speed_limit_exceeded 和 maintain_distance_failed。论文和图表将内部的 `out_of_bounds` 与
`timeout` 分别展示为 **Test-region departure** 和 **Destination not reached**，原始结果键保持不变。
图中按模型分面，并将六类从常规驾驶结果
排列到显式语言约束，便于观察每个模型的失败画像；该顺序不是因果划分，也不表示模型能力排名。

## 运行

在项目根目录运行，不需要 CARLA、驾驶模型或 API：

```bash
python3 -m evaluation.rq4.summarize_results
```

默认使用 `results/rq2/paper/selected_runs.csv` 和对应的 `audit.json`，
只选择其中已冻结的 VLAD-Fuzz 运行，不扫描最新目录自动替换来源。
输出默认位于 `results/rq4/summary/`，可用 `--output-dir` 修改。
可以用 `--selection` 和 `--rq2-audit` 提供另一套相互匹配的冻结来源。

## 输出与口径

- `category_summary.csv`：每个模型六类失败的数量、失败执行总数及占比，含零计数类别。
- `category_per_seed.csv`：同一口径的逐任务统计。
- `failure_index.csv`：每个失败执行一行，保留完整指令、类别、算子、执行指标和原始文件位置，供案例筛选。
- `audit.json`：来源文件哈希、逐运行记录摘要和统计规则。

分类采用最终 `failure_reason`（缺失时使用 `semantic_failure_reason`）与已启用
`triggered_checks` 的并集。同一执行每类最多计一次，不同类别可重复计入。
例如主原因为碰撞，但同时触发车道违规，则两类均计入。
速度、距离约束违反可能只保存在最终原因中，不能仅使用 `triggered_checks`。
不从原始 telemetry 布尔字段推断失败，尤其不能把已关闭的地图限速检查算入速度约束违反。
记录中的 `valid=False` 可以表示行为失败，不代表基础设施错误；实际执行错误和零帧记录会报错。

占比的分母为该模型或任务的全部失败执行，不是全部执行，也不是各类标签数量之和。
多标签占比之和可超过 100%。脚本检查冻结 metadata 哈希、模型和任务身份、四小时预算、
执行计数及失败记录数量；未知原因或无效执行不会静默丢弃，而是停止并要求核查。
原始结果不会被改写。

## 图表与解释边界

主图包含三个模型面板。每个面板使用相同的六类顺序和横轴范围，从而直接呈现单个模型的失败构成，
不再用额外标题把六类机械划分为三个组。正文先客观报告各模型占比最高的类别，再将整体顺序轻量解释为
从常规驾驶行为向显式指令约束过渡。由于搜索会针对被测模型自适应地改变后续输入，这些占比描述的是
当前任务和预算下暴露出的失败，而不是经过统一输入分布归一化后的能力排名。

LMDrive 和 BEVDriver 的距离保持违反为零时，正文必须明确：两者分别实际执行了 161 和 124 个
包含距离约束的测试，没有观测到指定 NPC 的最小距离低于当前容差阈值。零值不表示算子缺失，
也不足以证明整体距离保持或语言理解能力更强。速度约束占比同样不应被单独解释为约束遵守率；
如需比较约束执行能力，必须另行固定输入分布并使用全部适用执行作为分母。

暂不要求事件截图或案例复现。之后可以增加日志支撑的俯视示意图；
没有原始轨迹证据时，不能把示意图称为原执行的精确复现。
