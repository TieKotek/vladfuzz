# 驾驶指令质量评测说明

## 任务

每个 `case_xxxxxx` 目录包含一条待评估的英文驾驶指令。请结合第一视角图像和路线参考，判断该指令是否正确、清楚且适合作为驾驶任务。

- `image.png`：车辆起始位置的第一视角图像。
- `instruction.txt`：待评分的自然语言驾驶指令。
- `reference.txt`：模拟器根据该测试用例规划路线导出的结构化路线描述。它是判断指令中的驾驶动作、方向和先后顺序是否与规划路线一致的语义依据。它不包含待评分指令的推荐措辞，也不是要求模仿的措辞模板。
- `annotation.txt`：需要填写的评分文件。

请独立完成评分，不与其他评测者讨论，也不要修改除 `annotation.txt` 以外的文件。

## 评分标准

每条指令只能评为 `0`、`1` 或 `2`。

### 0：错误指令

指令不能正确表达路线要求，不能可靠地作为当前场景的驾驶任务。以下任一情况应评为 `0`：

- 核心动作方向错误，例如应左转却要求右转；
- 遗漏必要的转弯、变道、驶入或驶出等关键动作；
- 加入路线中不存在的关键动作；
- 与可见道路结构或路线参考明显冲突；
- 提到目标点、标记点或其他驾驶模型不可见的测试标注；
- 过于含糊、不是驾驶导航指令，或语言严重异常而无法理解。

### 1：正确但质量一般

指令表达的核心驾驶目标和动作顺序正确，可以作为测试输入，但存在以下一类质量问题：

- 表达过于笼统，未充分结合道路特征或其他有助于场景贴合的细节；
- 语言机械，接近模板的直接拼接；
- 多个动作的衔接不够自然或清楚；
- 含义可执行，但不像真实乘客会使用的简洁自然表达。

`1` 不是错误。只要驾驶目标正确且可执行，就不应评为 `0`。

### 2：正确且高质量

指令准确覆盖关键动作及其顺序，没有加入多余动作，并且表达自然、清楚、简洁且贴合当前道路场景。

> **Note:** 上述关于 `1` 和 `2` 的区分提示仅供参考。语言质量和场景贴合度具有一定主观性；评测者可以遵循自己的主观判断，并结合图像、路线参考和自然驾驶表达习惯，判断一条正确指令是否达到高质量标准。

## 错误类型

只有 `score=0` 时才填写错误类型；若有多个错误，可同时填写：

| error_type | 含义 |
|---|---|
| `wrong_maneuver` | 核心动作或方向错误 |
| `missing_maneuver` | 遗漏路线中的关键动作 |
| `hallucinated_maneuver` | 加入路线中不存在的关键动作 |
| `scene_mismatch` | 与可见道路结构或场景明显不符 |
| `target_marker_leakage` | 提到目标点、标记点等不可见测试标注 |
| `ambiguous_or_non_navigation` | 含糊或不是明确的驾驶导航指令 |
| `format_or_language_issue` | 空指令、严重不通顺、非英文或无法理解 |
| `other` | 其他错误，必须在 `notes` 中说明 |

若同时存在多个问题，可以填写多个错误类型，使用英文逗号分隔，并将最主要、最直接导致指令错误的类型放在第一位。不要重复填写同一标签。

## 填写格式

在每个 case 的 `annotation.txt` 中填写：

```text
score: 0
error_type: wrong_maneuver, scene_mismatch
notes: The instruction asks for a right turn, but the route requires a left turn.
```

填写要求：

- `score` 必须是 `0`、`1` 或 `2`；
- `score=0` 时必须填写至少一个 `error_type`；如有多个，使用英文逗号分隔，并将主要错误放在第一位；
- `score=1` 或 `score=2` 时必须将 `error_type` 留空；
- `notes` 通常可留空，但选择 `other` 或对评分把握较低时应说明原因；
- 完成后返回包含全部 case 的原目录。
